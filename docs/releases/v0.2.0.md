Second protected release of the reusable Agentic SDLC control plane.

Consumers should pin the reusable workflows, and the `platform_ref` input, to commit `02ce92be893484415d9f96f4abb75d3724cb7831`.

## Highlights
- **`sdlcctl onboard` / `doctor`**: one command generates the managed workflows, policy, hooks and ruleset. `doctor` then verifies the repository end to end, including credentials, runners, rulesets, the pins, and drift from the generated templates. (#139)
- **Issue leases**:
  - `claim`, `renew` and `release` coordinate sessions on an issue. Only lease markers from writers, `github-actions[bot]` or the configured Publisher App bot count.
  - `reusable-implement.yml` claims in `prepare` and renews at every stage boundary. It renews once more right before publishing, and a failed renewal stops the publish.
  - Its release is never hidden: there is no `|| true`. If it fails, an independent cleanup job retries it on `lease_cleanup_runs_on` (default `ubuntu-latest`), and that job fails red if the lease material cannot be restored.
- **Executable trust modes**:
  - In `strict`, the default, only a git, gh or hook interpreter that root alone can replace is run.
  - GitHub Actions and Claude Code cloud sessions are always strict.
  - The publication-decision commands (`check-diff`, `check-request`, `authorize-labeler`, `claim`, `renew`, `release`, `confirm-cloud-routine`) are always strict, whatever the policy or environment says.
- **Verification gates** run as one shell line, with `bash -e -o pipefail` (or `sh -e`). The `verify` job installs `[ci] python_version`. `run-gates` warns, but does not fail, when `python3` or `python` differs from that version.
- **Required approvals and runners**:
  - The "Protect main" ruleset's approving-review count is configurable. In the Actions modes it defaults to 1.
  - Updating an existing ruleset keeps every rule already in it.
  - Self-hosted runners must be acknowledged as ephemeral.
- **Preflight credentials**: route-mode preflight no longer hard-codes DeepSeek. `doctor` derives the required provider credentials from the installed registry and policy.
- **Pinned actions**: `actions/download-artifact` 8.0.2 and `actions/upload-artifact` 7.0.2. (#145, #148)

## Migration
1. **Required:** add `[automation] publisher_bot_login = "<app-slug>[bot]"` to `agentic-sdlc.toml`. With `sdlcctl onboard --apply`, this also sets `FORGE_LEASE_BOT_LOGINS`. Without it, the Publisher App's lease claims are not trusted and implementation runs fail at the claim step.
2. Move the `uses: atulg4/agentic-sdlc/.github/workflows/...@<sha>` pins, and the `platform_ref` inputs, to the commit above. The required inputs and secrets of `reusable-plan.yml` and `reusable-implement.yml` are unchanged; `lease_cleanup_runs_on` is new and optional.
3. **Optional:** re-run `sdlcctl onboard --force` (add `--apply` for the ruleset) to pick up the regenerated managed files.
   - On self-hosted runners, add `--runs-on <labels> --ephemeral-runners`.
   - Pass `--required-approvals 1` when a reviewer other than the PR's author exists.
   - Review the diff before you commit it: `--force` rewrites the managed files wholesale.
4. **Caveats:**
   - An organisation that disallows GitHub-hosted runners must pass `lease_cleanup_runs_on`. Otherwise the failure-cleanup job queues and never runs.
   - In `cloud-routine` mode the routine runs as root, so local checks cannot be tamper-proof against it. The enforcing control is the server-side ruleset with required review. At 0 required approvals, that boundary is not enforced.

Human merge remains required.
