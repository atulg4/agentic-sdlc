Third protected release of the reusable Agentic SDLC control plane.

Consumers should pin the reusable workflows, and the `platform_ref` input, to the commit the `v0.3.0` tag points at.

## Highlights
- **Ready-for-review publishing** (#164): `reusable-implement.yml` takes a new `open_as_draft` input, default `true`. A caller whose review workflow runs only on non-draft pull requests passes `false`, so the pull request opens ready for review. Clearing the draft flag afterwards with `GITHUB_TOKEN` does not work, because GitHub starts no workflow run for that event.
- **Pipefail is modelled, not assumed** (#155, fixes #153):
  - GitHub runs a `run:` step with no `shell:` as `bash -e {0}`, which has no pipefail. `doctor` used to treat a piped gate such as `pytest | tee out.txt` as enforced there, while a failing pytest still passed the step.
  - `doctor` now enforces a piped gate only under an explicit `shell: bash` or after the script's own `set -o pipefail`.
  - The generated `ci.yml` sets `defaults.run.shell: bash`, so CI runs the gates with pipefail, as `sdlcctl run-gates` already does.
  - The script parser fails closed on whatever can change whether a gate runs or fails: turning off errexit or pipefail (through `set`, `shopt -o`, a trap handler, `enable`, or an expansion), `set -n`, `exit`/`exec`/`return`, a gate behind `||`, a backgrounded command or group, `eval`, and a command named by an expansion. Queries that change nothing (`command -v`, `trap -p`, `shopt -q`, `[ ... ]`) keep a gate enforced.
- **Context packets** (#154): `sdlcctl context-packet` builds the complete, byte-budgeted model input for one builder, tester or reviewer run: task sections, policy limits, ranked repository evidence and, for reviewers, verification evidence bound to the candidate head. Untrusted text is fenced, and the packet's stable `packet_sha256` is recorded on the agent run. `dispatch-packet` wraps it in a dispatch envelope, and `attest-completion` and `attest-outcome` attest a run's result, and its verification or review outcome, against that envelope with the harness attestation key.
- **Schedule forecast** (#172): `sdlcctl schedule-forecast` gives deterministic P50/P80/P95 ETA ranges per unit and project from the usage ledger, the critical path, and a typed blocking reason for every unit that cannot run. It is read-only.
- **Forge Control Center** (#150): `sdlcctl control-center` builds one read-only, schema-versioned snapshot per portfolio from the project registry, the lifecycle ledger, a backlog and an incident document. `sdlcctl github-backlog` turns already-fetched GitHub issues and pull requests into that backlog and reports approved work that nothing is running.
- **Data residency fails closed** (#166): an explicit `allowedDataResidency: []` in the routing policy now permits no residency, as `allowedProviders: []` already permits no provider. It used to permit all of them.
- **Pinned actions**: `anthropics/claude-code-action` 1.0.264, `actions/setup-python` 7.1.0, `actions/create-github-app-token` 3.3.0. (#156, #161, #170)

## Migration
1. Move the `uses: atulg4/agentic-sdlc/.github/workflows/...@<sha>` pins, and the `platform_ref` inputs, to the `v0.3.0` commit. The required inputs and secrets of the reusable workflows are unchanged; `open_as_draft` is new and optional.
2. **Recommended:** re-run `sdlcctl onboard --force` to regenerate `ci.yml` with `defaults.run.shell: bash`. Until you do, `doctor` reports that file as template drift. Gates without a pipe behave as before.
3. **Caveats:**
   - `doctor` is stricter about the `test` job: a step whose command name is built from an expansion (`$x ...`, `` `cmd` ...``, `"$VENV/bin/python" ...`) is rejected, because it may be `eval`. Name the program directly.
   - A gate that pipes its output still needs pipefail: under `shell: sh` or with no `shell:`, add `set -o pipefail` or use `shell: bash`.
   - A routing policy that wrote `allowedDataResidency: []` meaning "allow all" now allows none. Delete the key to allow every residency.

Human merge remains required.
